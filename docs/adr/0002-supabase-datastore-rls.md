# 0002. Supabase 데이터스토어 + RLS(뷰 읽기 계약)

- 상태: 채택됨
- 날짜: 2026 (소급 기록 2026-08-01)

## 맥락
정적 프런트가 직접 읽을 수 있고, 스크래퍼가 쓸 수 있는 관리형 Postgres가 필요.

## 결정
Supabase(Postgres) 채택. 프런트는 **뷰(`v_*`)만 anon으로 SELECT**(계약), 원천 테이블 쓰기는 service key/MCP로만. anon INSERT는 RLS로 차단. 연간지표는 World Bank·최소 10년치.

## 대안
- 프런트가 원천 테이블 직접 조회: 스키마 변경에 취약, 계약 부재.

## 결과
- 장점: 프런트-데이터 결합도↓(뷰가 계약), 쓰기 권한 분리.
- 트레이드오프: anon 쓰기 불가 → 적재는 MCP/서비스키 필요. Free 티어 500MB·7일 정지 제약(→ 백업·아카이빙 필요).
